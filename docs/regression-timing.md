## 4. 고정 대기와 Viewer 재시작 (코드 정적 분석)

실행 기록에는 대기 시간만 따로 남지 않는다. 아래는 코드에서 센 추정이다.

| 항목 | 위치 | 회당 고정 대기 |
|---|---|---|
| 강제 재시작 `flows.cold_start(force_restart=True)` | 약 23회/기본 전체 | 21초(+ 로그인·DB 연결, 합계 40~60초) |
| 팝업 정리 `ui.ensure_ready` | XIPL_04(2회)·05·07 | 팝업이 없어도 8초 |
| 검사 닫기 `flows.close_examine` | WF01~15·XIPL 여러 곳 | 1.5 + 6~10초 |
| 설정 그룹 이동 `flows.open_group_page` | WF14 목록 수집 19페이지 × 2회 | 약 5초(그룹을 매번 다시 누름) |
| 설정 메뉴 숨김 확인 | WF13 `_menu_visibility` 49페이지 | 최대 3초씩, 약 150초 |
| 시험 검사 열기 `open_test_study` | WF03(2회)·05·09 | 약 18초 |

TC별 재시작: DICOM 1, WF02 1, WF03 2, WF04~12 각 1, WF13 3, WF14 2, WF15 1, XIPL 준비 1(+XIPL_03 1).
재시작만으로 기본 전체에서 약 15~20분을 쓴다고 추정한다.

`wait_new_group`(DB에 새 영상 그룹이 생길 때까지 기다림)은 WF02·WF07·XIPL_04·XIPL_07·`run-sys3d`에 이미 쓰인다.
NEXT_WORK P2의 `run-sys3d` settle=20 교체는 2026-09-03에 끝났고, 남은 `settle` 과제는 없다.

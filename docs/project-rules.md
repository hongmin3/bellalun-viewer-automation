# Project Rules

코드 변경 시 관련 절만 읽는다. 반복적으로 필요한 영구 주의사항만 담는다.

## 판정 근거

1. TC와 Step은 `../../Bellalun_Viewer_기본기능_Checklist_개정본.xlsx`의 `개정 TC` 시트에서 확인한다.
2. 기대 동작은 `../../지식/`의 관련 매뉴얼·사양·DICOM 문서에서 확인한다.
3. 사양서 검색은 `core/specs.py`, 체크리스트 로딩은 `core/checklist.py`의 기존 경로를 따른다.
4. 판정 `note`에는 기대값, 실제값, 사용 근거를 남긴다.
5. `traceability.json` 수정 시 `python tools/traceability.py`로 원문과 대조한다.

## 반복 실수 방지

- 같은 TC ID라도 다른 체크리스트에서는 내용이 다를 수 있다. 파일명을 먼저 확인한다.
- UI의 `+`, 선택, 대화상자 열기 등이 Update 없이 DB를 변경할 수 있다. 조회 전후 상태를 확인한다.
- `ui.click(row)`는 행 중앙을 누른다. 중앙에 버튼이 있으면 안전한 셀 좌표를 사용한다.
- Control ID는 화면마다 재사용된다. 문구를 읽고 후보가 모호하면 누르지 않는다.
- 콤보 표시 순서와 DB 값이 같다고 가정하지 않는다. 텍스트로 선택하고 저장 후 확인한다.
- 값이 결과에 안 보이면 제품 결함 판정 전 표시 옵션과 선행조건을 확인한다.
- 고정 sleep보다 창·로그·DB·파일·유효 프레임 등 실제 상태를 polling한다.
- GPU 없음은 GPU 의존 결과만 SKIP 근거가 되며 독립적인 UI/설정 판정은 면제하지 않는다.
- `finally` 정리 실패 기록은 `r.cleanup(...)`을 사용해 본 시험 판정을 가리지 않는다.
- 자동 치환이나 큰 구간 교체 후에는 컴파일뿐 아니라 diff와 속성 검사를 확인한다.

## 문서와 Git

- 사내 운영 상세 원본은 `../../프로젝트_상세.md`; HTML은 `tools/render_docs.py`로 생성한다.
- 공개 `README.md`는 사람용으로 자체 완결되게 유지한다.
- 수치는 `tools/report_numbers.py` 등으로 재측정하고 기준 시점을 함께 쓴다.
- `config.json`, 자격증명, 환자/런타임 데이터와 생성물은 커밋하지 않는다.
- 현재 상태만 문서화하고 과거는 필요한 commit 범위의 `git log`로 찾는다.

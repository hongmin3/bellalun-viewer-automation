## 원래 PC에 남긴 증거

아래 `work/`와 Reports/Evidence 및 설치 패키지는 Git 제외 자료다. 다른 PC에서 pull해도
생기지 않는다. 원래 PC의 인계 문서·필요한 승인 내부 자료를 별도로 전달받아야 한다.
사내 원문·Baseline·설정·환자/런타임 데이터와 내부 패키지를 공개 Git/Release에 올리지 않는다.

- `work/HANDOFF_20261015_candidate6.md`: 상세 위치·해시·검증 명령·다음 세션 프롬프트 안내.
- `work/final-suites-20261015-133607/verification.json`: 두 실행의 실제 상태.
- `Result_20261015_153714.json`: 기본 전체. report SHA256
  `50ecd9081990bc1b01b99a23a5618ac7d047aa71f535730758e17bdb39ac021a`.
- 해당 실행의 `snapshots/basic` 318파일 크기·SHA 일치, 첨부 120참조 누락 없음.
  `work/final6-basic-verdict-review.json`에 독립 판정 검토를 남겼다.
- `Result_WindowsUpdate_20261015_153914.json`: WU 조기 중단 결과.
  같은 실행의 `run-winupdate.log`와 `Evidence/ui/setup_startup_failed.png`부터 조사한다.
- `work/release-1.0.0-candidate6`, `work/final6-artifact-audit.json`,
  `work/final6-install-guard-review-normalized.json`, `work/final6-gui-validation-supplement.json`.

제품 자동화와 관찰자는 종료했다. 재개 전 현재 프로세스의 경로·생성 시각을 다시 확인한다.
과거 PID를 그대로 종료하지 않는다. 실제 제품 UI/입력/DB 실행 주체는 한 개만 둔다.

## 남은 순서

1. DICOM_Server_Setup 준비 실패의 화면·로그·기동/로그인·서비스/DB 상태로 원인을 확정한다.
2. 최소 수정 후 최종 설치 EXE의 live WU 전체를 완료하고 기존 수동 3건 외 10 PASS를 확인한다.
   `--from-regression` 과거 변환이나 새 SKIP으로 대체하지 않는다.
3. 소스/EXE를 바꾸면 정식 재빌드·설치 후 같은 새 EXE의 기본 전체와 live WU 전체를 모두 반복한다.
   환경 복구만 했다면 이전 BASIC 완료와 새 WU 실제 실행을 엄격히 검증해 연결한다.
   원본 실패 manifest를 덮어 완료로 만들지 않는다.
4. 최종 snapshot·제품 FAIL/MANUAL·WU XLSX Issues 시트의 기존 승인 예외를 독립 검토한다.
5. 관련 최종 문서/readiness/diff/commit/일반 push와 내부 로컬 전달을 마친다.
6. 상세 한국어 바탕 화면 TXT를 만들고 실제 보이는 PowerShell 창에 결과를 출력해 열린 채로 둔다.

별도 clean PC/VM·Windows 10·다른 관리자 계정 UAC는 미검증이다.
동일 Windows 11 호스트에서 PATH를 줄여 실행한 검증을 별도 PC 검증으로 기록하지 않는다.
GitHub 일반 push는 이전 인증 실패 상태다. 로컬 commit과 원격 push 성공을 구분하고
자격증명 출력·remote 변경·force push를 하지 않는다.

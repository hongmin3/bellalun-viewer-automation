# 실행 보존과 회귀 완료 후 자동 닫기

현재 설치판은1.0.16, 수정 소스는1.0.17 후보다. 1.0.13에서 추가한 공용 저장소·차이 복원·생성 Image 정리와 마무리 대기는 [검증 범위와 용량 모델](practical-preservation-validation.md)을 따른다. 아래 1.0.12 로컬 보존 설명은 이전 방식이며, 최신 실제 결과는 [progress.md](../progress.md)에서 확인한다.

## 실행 전 확인과 원상복원 선택

GUI에서 회귀를 시작하면 자동 준비 점검과 대상·변경·백업 범위를 확인한다. 이번 실행의 원상복원 여부를 체크하고 동의한다. 이전 실행의 체크를 자동 재사용하지 않는다.

CLI는 기본기능·WU·단독 USB에서 복원 여부를 명시한다.

```powershell
python run.py --config config.json run-regression --restore-after
python run.py --config config.json run-winupdate --no-restore-after
python run.py --config config.json run-wu09 --restore-after
```

복원 여부와 관계없이 사전 내용 사본과 SHA-256을 대조한다. 선택한 DB·파일의 원상복원 검증 범위는 실행 기록과 보고서에 남는다. DB 대조는 선언된 테이블/열 범위이며 전체 DB 바이트 일치라고 표현하지 않는다. 과거 사전 사본이 없었던 QC·Dose SR의 복원 미확인은 그대로다.

`preservation.storage_dir`를 지정하면 작업 폴더 `preservation/<run_id>`에는 journal·manifest를 두고 실제 사전/시험 후 사본은 공용 저장소 실행별 폴더에 둔다. 변경 없는 파일은 사전 사본을 참조하며 변경 파일만 순차 복원한다. 경로가 비어 있는 기존 모드는 로컬 전체 보존을 사용한다. 공유 실패를 로컬 전체 복사로 대체하지 않는다. 기존 사본·archive는 자동 삭제하지 않는다. 새 정리 예외는 정상 전체 회귀·선택 복원·서비스·완료 증명이 검증된 해당 실행의 생성 Image 격리 파일뿐이다. 보고서가 참조하는 증거는 `Evidence/preserved`로 해시를 대조해 복사한다.

미완료 보존 journal이 있으면 새 시험을 차단한다. 임의로 journal을 지우거나 이전 저장점만 복사해 실행하지 않는다. `python tools/recover_preservation.py --workspace <작업폴더>`로 조회하고, `--run-id <번호> --config <설정> --apply`로 복구할 실행을 선택한다. 백업 실패 후 제품이 시작되지 않은 경우에만 `--acknowledge-unstarted`로 미시작 사실을 확인할 수 있다.

## 공간·메모리와 실행 상태

디스크 점검은 데이터·백업·DB staging·보고서·증거·USB·복원 보관에 필요한 양을 물리 볼륨별로 합산한다. 설정 `preservation`의 바이트 예산은 보수적 운영 예약값이다. 제품 공식 경고 기준으로 취급하지 않는다. 예상량·여유를 조회하지 못하면 시작을 막는다. 메모리는 1 GiB 미만 차단, 2 GiB 미만 경고다.

저장점이 끝내 저장되지 않으면 이미 수행한 결과를 미완료 리포트로 남기고 다음 단계를 진행하지 않는다. 주 보고서 저장도 실패하면 `Runs/emergency`에 별도 JSON을 시도한다. 모든 저장 위치가 실패하면 영속 보존을 보장할 수 없으므로 오류를 표시한다.

실행 신원에는 코드·제품·Baseline·설정 지문과 실행 번호를 기록한다. 복원 journal이 달라졌거나 실행 지문이 다른 저장점의 재개는 거부한다. 표시 사본과 미완료 리포트는 정상 회귀로 인정하지 않는다.

같은 단계에서 새로 기록된 SQL 시간 초과·디스크 경고와 자동화 진입 예외가 함께 관찰되면 원인 증거를 남기고 후속 실행을 차단한다. 두 관찰의 인과 관계와 제품/환경 귀속은 미확정으로 표시하며 기존 제품 결함 기대값을 완화하지 않는다.

## 생성물 보관

`python tools/archive_artifacts.py --source <생성물폴더> --destination <새보관폴더> --compress`는 파일 목록과 필요 용량을 조회만 한다. 같은 명령에 `--apply`를 추가하면 새 폴더에 복사/ZIP을 쓰고 원문 SHA-256·manifest·영수증을 대조한다. `--verify <보관폴더>`로 원본 없이도 보관본을 다시 검증한다.

원본은 이동·삭제하지 않는다. Git 저장소·링크·junction·중첩 경로는 거부하며 복사 도중 원본이 바뀌면 성공으로 표시하지 않는다. 이 도구는 보존 사본을 만드는 기능이며, 로컬 원본 정리나 운영 보관 기간 결정은 별도다.
## 회귀 완료 후 60초

기본기능·WU의 시험과 선택한 복원·보고서·최종 실행 기록이 모두 끝나면 60초 카운트다운을 시작한다. 제품 FAIL이 있어도 정상 완주라면 적용한다. 중단·비정상 종료·UAC 취소에는 자동 닫기를 적용하지 않는다.

**자동 닫기 멈춤** 또는 다른 GUI 버튼을 누르면 그 회차의 자동 닫기가 취소된다. Space 등 키보드로 버튼을 실행해도 같다. 새 회귀가 완료된 경우에만 새 타이머를 시작한다. 검수 완료 여부와 자동 실행 완료는 별개다.

## 설치 기준과 제품 수명주기

`tools/collect_release_baseline.py --help`로 승인 DOCX의 대상 버전을 지정해 로컬 기준 JSON을 추출한다. 실제 config를 덮어쓰지 않으며 DB 버전이 원문에 없으면 추측하지 않는다. 기준이 없을 때도 실제 프로그램·구성 파일을 수집한다.

`tools/product_lifecycle.py --help`는 제품 패키지 읽기 조사, 고정 프로필 계획, 사전 보존, 명시 승인 실행, 재부팅 후 후속 검증을 제공한다. 실제 제품 설치 패키지와 검증된 무인 argv 증거가 없으면 실행을 차단한다. 자동화 도구 자체의 Inno Setup 인자를 Viewer 제품 설치에 사용하지 않는다. 재부팅 후에는 설치기를 반복 실행하지 않는다.

## 구조·효율·범위·원격 실행

UI 기동·전체 컨트롤 탐색·ID 탐색의 호출 수와 시간을 보고서에 모은다. 중첩된 시간은 단순 합산하지 않는다. XIPL의 저장 완료 후 Setting 닫기는 공통 구현을 사용한다. 실제 속도 개선은 새 실측 전에는 주장하지 않는다.

[자동화 범위 현황](followup-scope.md)은 `automation_scope.json`에서 생성한다. `python tools/scope_summary.py --check`로 일치를 확인한다. 상위 사내 문서의 최신 요약은 이미 같은 등급이며 과거 회차의 표는 이력으로 보존한다.

[원격 실행 안내](../remote/README.md)는 고정 실행 묶음, 인증 API, PC 잠금, 대화형 세션, 실행·취소·결과 회수를 설명한다. 로컬 HTTP/전송 시험과 실제 서버 배포·Windows PC 실행은 별도 검증이다. 서버·PC 계정·공유 VHD 잠금 조건을 확인하기 전에는 운영 실행을 시작하지 않는다.

대용량 묶음은 인증 HTTPS로 받고 해시를 확인한 캐시를 재사용한다. 진행 상태와 최근 로그를 함께 전달한다. 시작 후 정상·실패·취소 어느 경로든 정리·복원 완료가 확인되지 않으면 잠금을 유지한다. 현재 엔진의 강제 중지는 보존 작업을 끝내지 못할 수 있어, 중지 요청만으로 복원 성공을 표시하지 않는다.

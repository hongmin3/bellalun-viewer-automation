# TC 고도화와 VXvue 적용 검토

사용자 승인 범위: 사람 전용 TC의 SKIP 기록, WF14·WF15·WU11 보강,
WU09 실행 전 준비 확인. 이후 사용자가 실제 BellalunAuto GUI의 기본기능·WU 전체와
자동화 문제 수정·재시험을 추가 승인했다. 새 설치판 빌드·배포·재설치는 제외한다.

## VXvue 실제 코드 검토

fetch 후 ff-only pull은 기존 CHANGELOG·SPEC 등의 로컬 변경과 겹쳐 중단됐다.
변경을 stash/커밋/덮어쓰기하지 않고 보존했으며, 현재 checkout `f495cf8`을 읽었다.
Bellalun은 미푸시 저장점 후속 커밋을 보존하며 원격 5개 커밋을 일반 merge했다.

| VXvue 코드 | 실제 구조 | Bellalun 적용 | 후속 후보 |
|---|---|---|---|
| `core/run_matrix.py` confirmations/can_run | 모드별 사람 확인 목록과 자동 NG 차단을 별도 검증 | 공통 확인 2개와 WU USB 확인 2개. 시작창의 각 체크와 USB 재점검 | 모드별 준비 항목 데이터화 |
| `packaging/launcher.py` matrix CLI | 목록 표시 후 대화형 확인, 비대화형 명시 확인 | WU CLI/USB 단독의 목록과 `--prepared`, USB 실제 조회는 유지 | 실행 계획의 장기 재사용/만료 검증 |
| `core/run_matrix.py` checkpoint | 회차 결과를 저장하고 남은 회차 재개 | VXvue 재개 코드는 미이식. 기존 Bellalun 저장점의 교체 재시도는 실물 차단 수정으로 이번에 포함 | 기존 Bellalun 재개 경로 유지 |
| `core/user_launch.py` | 실패 항목별 원인과 사용자가 할 조치 분리 | USB 준비 실패 안내만 이번 범위에 적용 | Bellalun 준비 진단의 원인·조치 문구 정리 |
| `core/run_select.py` | 준비 점검 완료와 사람 확인을 실행 조건으로 사용 | 기존 Bellalun 동의·실행 기록 흐름 확장 | 자동 점검 상태를 시작창에서 일괄 표시 |

## 검증

신규 실패 시험을 먼저 확인한 뒤 구현했다. 목록 중간 시작, OCR 줄 판독, 오류 문자열,
밝은 영상 영역, 준비 확인 취소·USB 없음, GUI 전체 체크, 실제 WU 매핑을 검사한다.
최신 단위시험은 1,042 passed / 2 skipped / 299 subtests passed다. WU 매핑 검사와
정적 검사·readiness는 실패가 없다. 두 skip은 로컬 Inno 도구 경로 조건이다.

|---|---|---|---|
| 초기 개별 WF14·WF15·WU09 및 WU11 매핑 | 00:00~00:32:58(복원 포함) | 빈 Print Overlay 부모·원본 검사 선택·이전 Export 형식·검색 안내창 문제를 확인해 수정 | `work/run648/` |

| 소스 GUI WU 전체 1차 | 03:08:06~04:00:01, 엔진 51.7분 | PASS 2 / FAIL 7 / SKIP 4. 완료 화면·실행 기록 확인, 재시험 필요 | `work/run653-wu-gui/` |

기본기능의 36개 결과에는 준비용 2개가 포함된다. Install_07~09는 이번에 구현하지 않아
회귀 결과에 추가하지 않았다. Install_01은 승인 기준값 미확정 MANUAL을 유지한다.
지정 9개와 기존 WF16은 사유가 있는 SKIP이다.

WF14는 목록 13페이지·89행·849항목의 전체 판독과 상세값 복원 대조가 PASS였다.
TC 전체 FAIL은 기존 UPS 값 미복원이다. WF15는 16개 확인이 PASS이며 기대값은 완화하지 않았다.
XIPL03의 기존 Apply 후 표시값 복귀 FAIL도 유지했다.

기본기능 엔진 종료 뒤 GUI가 426,991자 로그 한 줄의 화면 계산에서 멈췄다. 파일 원문을
보존하면서 화면 한 줄을 4,096자로 제한했고, 후속 WU에서 GUI 완료 화면까지 확인했다.
최초 기본기능 GUI 실행 기록의 running 상태는 완료로 소급 수정하지 않았다.

WU 1차의 첫 오류는 제품 View Position Preset 조회의 SQL 시간 초과였다. 이후 제품의
12GB 디스크 경고창이 후속 입력을 막은 증거도 확보했다. 두 현상을 같은 원인으로 단정하지 않는다.
WU03이 원본 Tool 단계 미수행을 SKIP/일부 PASS로 표시하던 판정 결함은 별도로 수정했다.
필요한 Step 6·7 결과가 빠지면 원본 중단 사유를 포함한 FAIL로 기록한다. 과거 결과는 유지한다.

WU 1차 복원은 DB·작업 폴더·USB·이미지 inventory·원본 시험환자 파일 해시가 모두 일치했다.
기본기능 복원에서는 QC 기존 파일 6개의 수정 시각이 달랐으며 해당 파일의 실행 전 사본이 없어
바이트 복원을 주장하지 않는다. 후속 WU부터 QC 전체도 백업했다. 원본 영상과 기존 실패 증거는 보존한다.

공간 확보와 WU 재시험은 `work/run654-retry/`에 기록한다. 보관 자료는 파일별 해시 대조 후
USB의 시험 폴더와 다른 보관 폴더로 옮긴다. 재시험은 새 사본을 중복 생성하지 않고 현재 상태와
직전 원본 백업을 대조한 뒤 재사용한다. 최종 WU 결과와 등급 합계는 아래와 같다.

WU 재시험은 04:22:44에 실제 GUI에서 시작해 WF01·WF02·WF03 PASS를 확인했으나, 04:45:28 저장점 교체의 WinError 5로 비정상 종료했다. 새 전체 리포트가 없어 완료 회귀로 세지 않는다. 04:47:00 DB·작업·USB·이미지 복원 대조는 전부 일치했다.

원래 후속 목록의 저장점 재시도를 이번 실행 차단 수정으로 포함했다. 실제 Windows 읽기 핸들로 같은 교체 오류를 재현한 뒤, 오류 5·32·33만 8회/총 대기 1.95초 이내로 재시도하도록 수정했다. 지속 잠금은 원본 저장점 보존과 오류 전달을 유지한다. `work/run655-retry/`에서 전체 시험과 새 GUI 재시험을 완료했다.

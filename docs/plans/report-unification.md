# Bellalun·VXvue 결과 보고서 통일 계획

**Goal:** 두 제품에서 같은 읽는 순서와 조작으로 결론·원인·실제값·증거를 찾는다.
**Spec:** Bellalun SPEC.md REQ-REPORT-001, VXvue SPEC.md REQ-REPORT-003. 사용자 요청으로 VXvue 작업 브랜치를82bb189로fast-forward pull했다.

## 비교와 결정

VXvue의 실패·수동 확인 우선, 검색·판정 필터, TC/준비점검 분리, Step1회 표시·PASS접기·긴비고접기·인쇄 전체펼침을 채택한다. Bellalun의 알려진 결함/연쇄 미수행 구분, 차단 해제조건·미검증 범위, dict/list 보존과 실제 전체시간을 유지한다.

단순 색상 교체는 정보 찾는 방법이 달라 남으므로 제외한다. 제품별 renderer 전체를 복사하면 판정·TC 매핑이 섞일 위험이 있으므로 제외한다. 동일한 독립 표시 모듈을 양쪽에 두고 각 제품의 기존 TC/원문/판정 어댑터에서 호출한다. 런타임에 다른 저장소를 import하지 않는다.

## 보호할 것

- 기존 JSON/CSV/TXT 계약·판정·TC ID·체크리스트 원문·증거를 보존한다. HTML 표현만 통일한다.
- VXvue의 제출용 자동화 등급 숨김 정책을 유지한다. Bellalun의 등급·커버리지는 접힌 부록으로 보존한다.
- 확인하지 않은 결함을 등록된 결함이나 새 제품 결함으로 분류하지 않는다.
- 전체 실행 시간이 없는 과거 WU 보고서는 미기록으로 표시한다. 재개는 이번 실행 구간을 쓴다.
- 원본 결과를 수정하지 않고 실제 결과의 별도 HTML 보정본·비교본을 만든다. 제품 UI·DB·전체 회귀는 실행하지 않는다.

## 보존과 마무리

공용 저장소에 실행 전 사본과 시험 후 변경·신규 파일을 SHA-256으로 검증해 보존한다.
변경 없는 파일은 사전 사본을 참조하며 로컬에는 최대 단일 파일만 순차 staging한다.
저장소 연결·identity 불일치는 차단하고 로컬 전체 복사로 전환하지 않는다.

공유 보존·복원을 선택한 전체 회귀는 제품 시작 전에 `execution_finalization_pending`을
기록한다. 파일·DB 복원만 verified여도 서비스·완료 증명·정리·최종 저장이 끝나기 전에는
다음 실행을 막는다. 서비스 실패, 완료 증명 저장 실패, 정리 직전 중단과 최종 보고서 실패를
합성 시험으로 재현했다. 미시작 확인은 제품이 시작되지 않았다는 기존 조건에서만 잠금을 해제한다.

정상 전체 회귀와 선택 복원·서비스·원본 완료 증명을 확인한 뒤 해당 실행의 Image 격리 파일만
정리한다. 제품 FAIL 자체는 정상 완주라면 정리를 막지 않으며 FAIL 결과는 유지한다.
정리 재개는 `tools/recover_preservation.py --workspace <작업폴더> --run-id <번호>
--config <설정> --apply --resume-image-cleanup`을 사용한다. 원본 완료 증명·해시가 필수이고
DB 복원은 반복하지 않는다. 증명이 없는 중단은 자동 정리하거나 정상 완료로 승격하지 않는다.
보고서·receipt 저장까지 성공해야 마무리 잠금을 해제한다.

중단 실행을 `tools/recover_preservation.py --apply`로 복구한 뒤 마무리 대기가 남는 경우,
원래 실행의 중단/비정상 상태와 파일·DB·사본·서비스를 재확인해 별도 중단 복구 영수증을 남긴다.
영수증 저장까지 성공하면 다음 실행을 허용한다. 생성 이미지는 지우지 않으며 원래 판정을 정상완주로 바꾸지 않는다.
정상완주 증거 파일이나 이미지 정리 대기가 있으면 이 경로로 해제하지 않고 원래 정리 재개 조건을 따른다.

실제 SMB 합성 시험은 재부팅 뒤 인증 오류 `WinError 1326`으로 전용 시험 폴더 생성 전에
중단됐다. 실제 NAS·긴 UNC·단절 복구 통합 통과로 기록하지 않는다. 저장된 자격증명이나
다른 공유 연결을 변경하지 않았다. 로컬 합성 공유 시험과 실제 SMB 시험은 별개다.

사용자는 복구를 시도해 연결되지 않으면 이번 NAS 검증을 제외하도록 지시했다.
현재 Windows 계정으로 해당 공유에 한정해 연결을 시도했으나 인증 오류86/1326이 유지됐다.
이번 실행은 별도 로컬 저장소를 GUI에서 선택했다. NAS 자동 대체 동작이나 실제 SMB 통과를 뜻하지 않는다.
사용자가 별도로 제공할 영상은 없으며, 제품 DemoImage의70개/1,582,850,400bytes를 확인했다.
회귀에서 Demo 획득이 가능한지 검증하며 과거1,938개 영상을 복구했다고 주장하지 않는다.

## WF14와 XIPL03

근거는 SRS 01-10-60 물리486쪽 Import 표와 SRS 03-50-230 물리765–768쪽이다.
사내 원문은 공개 저장소에 포함하지 않는다.

- WF14: UPS 모델만 Import 복원 비교에서 분리하고 Import 직전 변경값 유지를 별도로 검증한다.
  나머지 Device와 목록·DB 대조는 유지한다. 과거 UPS 미복원 제품 결함 분류는 기대값 오류다.
- XIPL03: 우측 XTP 기본값, 실제 `.img` Recon/Syn 10개 적용값과 영상 Overlay를 별도로 확인한다.
  Apply timeout에도 DB·파일 증거를 먼저 남긴다. 같은 Study의 최신 영상 사본을 읽고 Viewer
  재시작 후 동일 검사·저장값을 확인한다. No GPUS 한 줄로 산출물을 SKIP하지 않는다.
- Overlay 버튼 탐색과 캡처는 유일한 Post Reconstruction 창 안으로 한정하고 실제 영상 종류
  선택을 확인한다. Apply 직전부터 완료 창/로그를 확인할 때까지 후속 입력을 차단한다.
  timeout 뒤 파일 읽기·증거 쓰기까지 실패해도 차단을 유지하며 기본/WU의 다음 TC로 넘어가지 않는다.
- 잘못된 기대값에 대한 기존 WU/릴리스 결함 제외 목록은 비웠다. 과거 FAIL 리포트를 새
  회귀 gate에 통과시키지 않는다. 원시 리포트와 기존 이력은 수정하지 않는다.

과거 WF14는 별도 사양 재평가 PASS 근거가 충분하지만 실제 새 회귀의 PASS가 아니다.
XIPL03은 Recon/Syn 결과·Overlay·파일·재시작의 실물 증거가 부족하므로 전체 PASS로 바꾸지 않는다.
신규 Overlay 판독은 과거 Syn 캡처에서 X/6/14/6/15를 읽었으며 실제 새 빌드의 버튼 선택·Recon
판독·재시작 경로 수용은 남아 있다.

## 실물 수용 선행조건

현재 DATA는 PATIENT/STUDY 각 1, SERIES/INSTANCE/INSTANCE_GROUP/FRAME 0, QC_STUDY 1이다.
후속 실행에서 이 상태의 DB4개를 BACKUP/VERIFYONLY·사본 해시·48개 선언 조회 범위로 검증했고,
Config/Image/ImageTemp/Export/ExportSettingTemp/XIPL/QCExport/DemoImage 사전 사본도 해시 대조했다.
Image는0개이며 DemoImage70개다. Baseline 복원은 아직 수행하지 않았다.
승인 Baseline은 DB 4개뿐이며 전체 Image와 manifest가 없다. 일부 보존 영상은 과거 1,938개
전체 원본을 대신하지 않는다. 현재 4DB·Image·QC 상태를 보존한 뒤 승인 Baseline을 적용하고
필요한 실영상을 확보·대조해야 한다. 영상이 없으면 전체 복구나 회귀 완료를 주장하지 않는다.

새 납품 ZIP 해제 → Setup 설치/업데이트 → 설치된 Auto GUI → 기본기능·WU 전체 → 선택 복원·결과·
Image 정리 → 정상 완료 60초 자동 닫기 및 모든 취소 조건을 실제로 검증해야 한다.
빌드 EXE·해시·약 3–4시간 이상의 예상 점유·DB/설정/USB 변경을 제시하고 승인받는다.
잠긴 화면·로그아웃은 우회하지 않는다. CLI·합성 시험은 이 수용을 대신하지 않는다.

P10의 실제 제품 설치 패키지·검증된 무인 인자·DB ReleaseVersion 기준과 P14의 실물 Windows
대상/계정·WinRM·공유 VHD 잠금 수용은 남아 있다. Ubuntu SSH 검증으로 대신하지 않는다.

현재 보관된 제품 패키지의 Install/Viewer 설치 관련 7개 파일은 읽기 전용으로 목록·크기·해시를
수집했다. 현재 `DATA.SOFTWARE_VERSION.Version`은 `1.0.12.105`이며 4DB의 사용자 테이블에는
`ReleaseVersion` 이름의 열이 없었다. 이 관찰값은 Release Note 승인 기대값을 대신하지 않는다.
설치 XML의 하위 구성요소 인자는 최상위 설치 wrapper의 검증된 무인 실행 프로필 증거가 아니다.

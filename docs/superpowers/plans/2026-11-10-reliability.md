# 설치판 실패 경로 보강 계획

> 실행: 현재 세션에서 TDD로 구현하고 독립 코드 검토 후 전체 코드 검증한다. UI 회귀는 별도 승인 대기다.

**목표:** run542에서 관찰한 자동화 실패를 안전한 상태 확인과 증거 보존으로 줄인다.
**사양:** SPEC.md REQ-OCR-001/002, REQ-REGRESSION-001/002, REQ-DIST-005.
**구조:** 공통 OCR 선택과 기존 UI·목록 수집기를 확장한다. VXvue의 상태 재조회·영역 판독 원칙을 참고하되 제품 ID·시각 임계값은 이식하지 않는다.

## 제약과 재사용

- OCR 0.85/0.15/35, 최대4판독, 짧은 문구 완전일치·모호/판독불가 거부를 유지한다.
- 기존 WF14 UPS·XIPL03 Step9 허용 목록과 수동 범위, 제품 기대값은 변경하지 않는다.
- 설치판·설정·DB·DICOM·USB·원본 보고서는 변경하지 않는다.
- 기존 core/ocr_selection.py, print_overlay.py, setting_lists.py, viewer_processing.py 및 관련 단위시험을 사용한다.
- 미확정 XIPL05 원인은 해결로 단정하지 않고 대기 구간 진단을 보강한다.

## 작업

1. [x] OCR: 잘린 행을 스크롤로 온전히 드러낸 뒤 한 번 캡처한다. 행을 재조회하고 대상 HWND/ID가 달라지면 중단한다. 잘린 경쟁 후보를 단순 제외하지 않는다. tests/test_print_overlay_selection.py에 재현·경합·소실 테스트를 추가하고 RED→GREEN을 확인한다.
2. [x] 팝업: 첫 ItemList 대신 클릭한 콤보에 인접한 유일한 팝업을 제한 시간 동안 재조회한다. 지연·다른 팝업·경합·시간초과 테스트를 추가한다.
3. [x] 목록: DB 전체 항목 수가0임을 확인한 경우에만 존재하는 Position 목록에 expected_count=0을 전달한다. DB 미확인·항목존재·컨트롤소실은 실패를 유지한다.
4. [x] Post Reconstruction: 이미 열린 상태와 버튼·두 필수 컨트롤을 함께 확인한다. 클릭1회 후 제한 대기하며 부분 상태·지연·시간초과를 테스트한다.
5. [x] 증거: CWD와 독립된 실행 Context의 OCR 증거 위치를 지정한다. Q.C 촬영 실패에 단계별 관찰 정보를 남기고 실제 로그 실패를 PASS로 바꾸지 않는다.
6. [ ] 전체 단위시험·정적7종·readiness·workspace검사·독립검토를 수행한다. 문서와 추적성을 갱신하고 정상 commit/push한다. 새 후보 빌드·전체 기본+WU UI 실행 범위를 준비해 승인받는다.

## 검토 초점

실행 기록: 작업1~5 구현과 재현시험·903개 전체 시험·독립 재검토 완료. 작업6의 최종 문서/게시/후보 빌드 정리 중이다. UI 회귀는 승인 대기이며 실행하지 않았다. DB 전체 항목0이 아닌 경우는 근거 없는 Overlay 이름-DB 키 매핑을 새로 도입하지 않고 기존 전수 수집을 유지하기로 결정했다.

잘린 후보의 미판독을 숨기지 않는가, 스크롤 후 낡은 컨트롤을 클릭하지 않는가, 다른 팝업을 선택하지 않는가, 빈DB와 미로딩을 구별하는가, 창의 일부만 떠도 성공으로 처리하지 않는가.

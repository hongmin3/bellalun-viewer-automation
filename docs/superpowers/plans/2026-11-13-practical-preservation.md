# 공용 보존과 용량 기준 구현 계획

**목표:** 로컬 전체 영상 3중 복사와 USB 일괄 여유 기준을 개선하고, 녹화 없이 설치판 사용자 흐름을 검증한다.

**설계:** [공용 보존 저장소와 용량 기준](../specs/2026-11-13-practical-preservation-design.md).

**기술:** 기존 Python·Tk·Windows 파일/볼륨 API. 실제 주소와 설정은 공개 저장소에 넣지 않는다.

## 제약

- 실제 config와 제품/DB는 구현 시험에서 변경하지 않는다.
- 기존 AGENTS.md 변경은 보존한다.
- 실제 자산이 있는 현재 checkout에서 파일 소유권을 나눠 작업한다.
- 제품 UI 회귀는 새 빌드와 범위를 제시한 뒤 수행한다.

## 작업

- [x] 소스 구현·합성 시험 — 공용 저장소와 차이 복원: 로컬 journal, 저장소 식별, 사전/시험 후 사본, 순차 교체와 재개, 기존 형식 호환. 실패 시험을 먼저 추가한다.
- [x] 소스 구현·합성 시험 — 용량 계산과 실행 연결: UNC 조회, C/USB 기준 분리, 최대 단일 파일 임시량, DB staging, 복구·증거 경로 연결. 실제 메타데이터 예산을 다시 계산한다.
- [x] 소스 구현·합성 시험 — 설정 화면과 안내: 보존 저장소 선택, 기존 설정 보존, 기본 점검의 검증 범위 표현, 녹화 제외.
- [x] 소스 구현·합성 시험 — 통합: 공통 API를 연결하고 충돌·미완료 색인·복원 신원·원격 receipt를 확인한다.
- [x] 소스 구현·합성 시험 — 생성 이미지 정리: 공유 사본·복원·서비스 검증 후 이번 실행의 Image 격리 파일만 지우고, 미복원/실패/소유권 불일치/사본 불일치에는 삭제하지 않는다. 실패 시 자동 닫기를 막는다.
- [ ] 합성 파일로 실제 공유 보존/복구 probe, 전체 시험·정적 검사·독립 검토.
- [ ] 문서와 로컬 게이트·커밋·push·후보 빌드.
- [ ] ZIP 해제·Setup 설치·설치판 GUI·승인 범위 회귀·복원·보고서·60초 닫기/취소 검증.

## 현재 검증 경계

소스 체크 표시는 실제 SMB/제품 수용 완료가 아니다. NAS 합성 probe는 인증 WinError1326으로 미실행, 신규 설치판 전체 회귀와 실영상 복구는 남아 있다. 최신 상태는 progress.md와 docs/practical-preservation-validation.md를 따른다.

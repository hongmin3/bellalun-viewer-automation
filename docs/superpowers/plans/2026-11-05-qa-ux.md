# 첫 사용자 QA 흐름 구현 계획

기준: SPEC REQ-QA-001~005. 요청된 구현을 이 세션에서 수행한다.

## 공통 제약과 조사 근거

- 기존 TC 기대값·PASS 기준·환경 gate·설치기·엔진을 재사용한다.
- `bellalunauto/gui.py` RunController와 `app.py` completed_report·diagnostics, `core/automation_health.py` 상태 파일을 확장한다.
- 공유 ZIP과 실행 계획 구현은 현재 없다. 별도 모듈로 작성한다.
- 사내 설정·원문·Baseline·환자 자료는 공개 커밋에 포함하지 않는다.
- 기존 미커밋 SPEC 보존, main/origin 8051de2 확인. ignored 팀 설정·자료가 필요하므로 실제 checkout에서 파일 담당을 분리한다.

## 공유 계약

- `build_plan(layout, config, action) -> dict`, `format_plan(plan) -> str`: 조회 전용 실행 계획.
- `RunRecord`: workspace/Runs/run_id/run.json에 계획·동의·진행·보고서 저장. GUI 취소는 실행하지 않는다.
- 공유 ZIP 입력은 명시적으로 선택한 보고서 파일과 review.json, 선택 범위의 증거다. 검증은 제품·네트워크를 사용하지 않는다.

## 작업

1. REQ-QA-001: `bellalunauto/runplan.py`, `tests/test_runplan.py`. Baseline/DB/변경·복구 정책 실패 시험 → 구현 → 성공 확인. GUI 동의 체크 전 시작 금지.
2. REQ-QA-004: `bellalunauto/share.py`, `tests/test_share_package.py`. 상대 링크·민감 범위·누락/추가/변조/경로 탈출 실패 시험 → 구현 → 성공 확인.
3. REQ-QA-002~003: `bellalunauto/runs.py`, GUI/CLI 통합, `tests/test_qa_runs.py`. 오래된 보고서 배제, 중단/UAC/비정상 종료, 미검토 TC 완료 거부, 자동 판정 보존을 실패 시험 후 구현한다.
4. REQ-QA-005: 준비 점검 행별 해결·설정 열기·재점검 GUI를 추가한다. gate는 기존 경로 그대로 유지한다.
5. SPEC TEST-QA와 추적성·인수표·사용법을 갱신한다. 전체 단위시험·정적 7종·readiness·독립 검토 후 --team-settings 후보를 WMI 분리 빌드한다.
6. Setup 실측·한글 공백 경로 오프라인 공유 검증, VXvue 점유 확인. 최종 EXE 해시·두 묶음 약 4시간·DB·USB 범위를 제시하고 답변을 기다린다. 실측하지 않은 조건은 미완료로 남긴다.
7. 실제 결과로 문서와 HTML을 갱신하고 로컬 게이트 통과 뒤 commit/일반 push. #80은 실제 완료 조건을 채웠을 때만 닫는다.

## 검토 초점

- UAC 승인만으로 데이터 변경 실행이 가능한 경로
- 다른 실행·오래된 보고서가 현재 결과로 연결되는 경우
- 중단·빈 결과를 검수 완료로 오인하는 경우
- 선택하지 않은 민감자료·외부 파일·경로 탈출이 ZIP에 섞이는 경우
- 준비 실패 해결 버튼으로 gate가 우회되는 경우

# 공용 보존 저장소와 현실적인 용량 기준

사용자는 C:에 수백 GiB를 예약할 수 없으며 USB 기준도 완화하도록 요청했다. 공용 저장소 백업과 변경 파일 복원 방식을 선택했다. 화면 녹화는 새 검증에서 제외한다.

## 선택한 방식

전체 자료를 로컬에 여러 벌 복사하는 방식은 현재 PC에서 실행할 수 없다. 예약 숫자만 낮추면 실행 중 용량 부족이 생긴다. 사용자가 선택한 방식은 공용 저장소에 실행 전 사본과 시험 후 자료를 검증해 보존하고, 로컬에는 변경 파일 복원에 필요한 임시 공간만 쓰는 것이다.

운영 저장소 주소는 PC별 설정으로 받으며 공개 저장소에 실제 주소를 넣지 않는다. 로컬 압축만 사용하는 대안은 현재 자료가 충분히 압축된다고 보장할 수 없어 선택하지 않았다.

## 보존과 복원

- 로컬 `preservation/<run_id>`에는 내구성 있는 journal과 manifest를 유지한다. 공유 저장소가 끊겨도 미완료 실행을 발견하고 다음 실행을 차단한다.
- `preservation.storage_dir`가 있으면 실제 사전 사본과 시험 후 보관 자료는 해당 저장소의 실행별 폴더에 둔다. 저장소 식별자를 로컬 기록과 대조한다. 연결 실패에 로컬 사본으로 자동 전환하지 않는다.
- 실행 전 파일 목록·빈 폴더·존재 여부·파일 SHA-256과 DB 사본을 검증한다. 검증 전에는 제품 시험을 시작하지 않는다.
- 복원 전 현재 파일 목록을 확보한다. 새 파일과 변경 파일은 공유 저장소에 복사하고 해시를 검증한다. 변경 없는 파일은 이미 검증한 사전 사본을 참조할 수 있다. 시험 후 DB도 별도 보존한다.
- 공유 보관 검증 후에만 작업 경로를 변경한다. 변경 없는 파일은 그대로 유지한다. 바뀌거나 사라진 파일은 한 파일씩 같은 볼륨의 임시 파일로 복사·fsync·해시 확인 후 교체한다. 추가 항목과 형태가 충돌한 항목은 실행별 격리 경로로 옮긴다.
- 파일별 진행 단계를 먼저 기록하고 중단 후 재개한다. 이미 완료한 교체를 중복 수행해 사전 사본이나 이전 archive를 덮어쓰지 않는다.
- 사전 사본·시험 후 archive·기존 백업은 자동 삭제하지 않는다. 검증한 공유 사본 뒤 로컬 변경 파일을 교체하는 것은 사용자가 선택한 복원의 일부다. 이 모드에서 전체 Image를 로컬 holding으로 다시 복제하지 않는다.
- 사용자는 회귀 후 생성 이미지 자동 정리도 요청했다. 공유 사본·파일/DB 복원·서비스 복구가 모두 검증된 실행에서, 해당 실행의 Image 격리 경로에 남은 생성 이미지만 제거한다. 경로 소유권·각 파일의 공유 사본 해시를 다시 확인한다. 기존 이미지·다른 실행·USB·설정·NAS 사본은 삭제 대상이 아니다. 복원을 선택하지 않은 실행은 DB 참조를 유지하기 위해 이미지 삭제도 생략하고 사유를 기록한다. 정리 실패는 정상 완료·자동 닫기를 막는다.
- 최종 성공은 전체 복원 상태와 DB 비교 범위 및 서비스 RUNNING까지 확인한 뒤에만 기록한다. 미확인 종료에는 자동 닫기를 적용하지 않는다.
- 저장소 설정이 없는 기존 로컬 실행과 기존 journal은 현재 형식으로 계속 읽고 복구한다.

## 용량 기준

다음 기본값은 구현자가 정한 운영 제안이다. 제품 공식 최소 사양은 아니다.

| 용도 | 기본값 또는 산정 |
|---|---|
| 제품 볼륨의 여유 | 볼륨별 2GiB |
| USB 여유 | 256MiB |
| USB 시험 생성량 | 별도 512MiB, 기존 자료의 복원 임시량 추가 |
| 일반 root 생성량 | 기존 설정을 유지하되 USB는 별도 기준 적용 |
| 보고서·로그 | 256MiB |
| 정지 스크린샷 증거 | 512MiB, 화면 녹화 없음 |
| 공용 저장소 | 전체 사전 사본·DB 및 시험 후 변경량의 안전한 상한 |
| 변경 파일 복원 임시 공간 | 같은 볼륨에서 순차 복원하는 최대 단일 파일 크기, DB staging 별도 |

동일 볼륨의 여유는 중복 합산하지 않는다. USB에도 제품 볼륨의 기본 여유를 일괄 적용하지 않는다. UNC 공유의 여유를 Windows API로 읽고, 조회 실패는 차단한다. 링크나 경로 바깥 참조로 기준을 우회하지 않는다.

실제 예산은 새 구현으로 다시 산정한다. C:41GiB에서 실행 가능하다는 결론은 새 계산과 실제 저장소 probe 전에는 내리지 않는다.

## 사용자 흐름과 범위

배포 ZIP을 새 폴더에 해제하고 Setup으로 설치한 뒤, 설치된 BellalunAuto의 설정과 GUI에서 시험한다. 소스 단위시험과 설치판 사용자 흐름은 구분한다. 화면 녹화·편집·업로드는 요구사항도 수용 조건도 아니다. 기존 역사 자료를 새 녹화 의무로 재사용하지 않는다.

실물 회귀 시작 전에는 새 EXE와 해시, 기본기능/WU 범위, 예상 시간, PC 입력 점유, DB 복원·USB 사용을 제시한다. 이번 설계·구현은 제품 UI 실행 승인을 대신하지 않는다.

## 검증

- 기존 로컬 보존·복구 회귀 시험 유지.
- 공용 저장소 준비/완료/중단, 연결 단절, 저장소 바뀜, 로컬 미완료 색인, UNC 긴 경로.
- 변경 없음/수정/삭제/추가/파일·폴더 충돌/빈 폴더, 동일 크기·시간의 다른 내용, 교체 단계별 중단·반복 복구.
- 파일과 DB의 사전/시험 후 사본이 모두 남는지 확인.
- 제품·USB 볼륨별 여유, 최대 단일 파일 임시 공간, 실제 부족/조회 실패 차단.
- 설정 저장이 기존 계정·경로·미지 필드를 보존하는지 확인.
- 실제 공유에는 합성 파일로만 probe하고, 실제 제품 자료 복사와 회귀는 준비 완료 후 승인된 흐름에서 수행.

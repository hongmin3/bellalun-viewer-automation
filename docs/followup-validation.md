# 1.0.12 후보 로컬 검증

기준 변경: f247d21 이후 P1~P14와 GUI 완료 60초 자동 닫기. 원격 보완까지 포함한 최종 전체 소스 시험은 1257 passed / 302 subtests passed(127.47초), 건너뛴 시험 0개, 시험 전후 소스 해시 변경 0이었다. 명령은 Inno 경로를 지정한 `python -X utf8=0 -m pytest tests -q`이며, Windows 기본 문자셋에서도 UTF-8 검증 JSON을 읽도록 시험 2곳을 보완했다. 로그는 로컬 work/followup-remote-release-tests.log에 보존한다.

- GUI: 실제 격리 Tk 창으로 60초 경계·멈춤·모든 버튼과 키보드 취소·늦은 콜백·저장 중 종료 보류를 확인했다. 사용자 Viewer는 조작하지 않았다.
- 파일/DB 보존: 실제 임시 파일 사본·SHA-256·같은 크기/시간의 다른 내용·추가/삭제·중단 복구·공통 CLI 진입점을 확인했다. DB adapter는 실패 주입 시험이며 실제 DB 복원은 이번에 실행하지 않았다.
- 실패 기록: 실제 WU 체인에 지속 저장 실패를 주입해 마지막 결과 보존, 미완료 리포트와 정상 완주 제외, 기본기능 비상 JSON을 확인했다.
- 신원/재개: source/config/Viewer/Baseline 지문과 verified 복원 journal이 바뀌면 재개를 거부한다. unknown 신원을 깨끗한 실행으로 승격하지 않는다.
- 원인/효율: 새로 append된 단계 로그와 실패를 연결하고 과거 로그를 제외한다. 원인 귀속은 미확정이며 제품 기대값은 유지한다. UI 비용은 중첩 inclusive 집계이므로 전체 행을 실행시간처럼 합산하지 않는다. 실물 속도 개선은 미확인이다.
- 설치: 승인 DOCX 파서와 별도 기준 JSON, 실제 구성 수집, 프로필 검증 및 합성 설치 프로세스, CLI prepare/apply/resume·복원 경계를 확인했다. 실제 제품 설치/제거·재부팅은 하지 않았다.
- 원격: localhost 인증 HTTP와 격리 브라우저에서 제출/조회/취소/수집/다운로드를 확인했고 JS 오류는 0이었다. 가짜 WinRM 경계에서 대화형 세션·task·완주 신원·전송 해시를 확인했다. 실제 Windows PowerShell로 수집 경로의 상위 junction 거부와 정상 파일 회수를 검증했다.
- 원격 후속: 73개 시험에서 인증 binary 다운로드·캐시·구형 묶음 갱신·단일 진행 조회·시간 제한과 시작 후 정리 미확인 잠금을 확인했다. 100MiB 모형은 새 전송 2회, 캐시 적중 1회의 WinRM 호출이었다. 실물 전송 속도 측정은 아니다. 독립 검토의 추가 중요 결함 3건을 수정하고 재검토를 마쳤다.
- 보관: 실제 복사/ZIP·manifest/receipt·변조/원본 변경·용량 부족·Git/링크/junction 거부를 확인했다. 실제 기존 생성물은 이동하거나 삭제하지 않았다.

독립 검토의 중요 결함 7건을 수정했고, 추가 보관 도구 검토에서 Important/Critical 지적은 없었다. 제품 UI, 새 EXE의 기본기능/WU 수용, 실제 제품 설치 수명주기, 서버 배포·실제 원격 PC 실행은 별도 승인과 환경 준비가 필요하다. 기존 제품 FAIL과 사전 사본 없는 과거 QC/Dose SR의 복원 미확인을 유지한다.

사내 원문·계정·설정·데이터·추출 기준 JSON·실행 로그·컴파일 산출물은 공개 저장소에 포함하지 않는다. 실제 실행·배포 성공을 로컬 시험 통과로 대신하지 않는다.

후보 빌드는 `release/1.0.12/BellalunAuto-1.0.12-candidate-setup.exe`다. 빌드 선행 시험은 당시 1216개·302 subtests가 통과했다. 실제 EXE의 `--version`은 `BellalunAuto 1.0.12`, `--help`는 사용법을 출력했고 둘 다 종료 0이었다. Setup과 build-info의 SHA256SUMS도 일치했다.

build-info의 source_commit은 `eee10553c47342f30ef0890a6a7bbf386617b991`, source_dirty는 true다. 원격 후속은 별도 소스 변경이며 컴파일한 GUI·엔진·core는 이 커밋과 같음을 확인했다. 기본기능·WU 게이트 입력이 없어 정식 수용 통과로 표시하지 않는다. 기존 설치판 1.0.11은 유지한다.

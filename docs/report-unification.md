# VXvue·Bellalun 공통 보고서 검증

## 비교와 적용

사용자 요청으로 VXvue의 현재 작업 브랜치를 원격82bb189까지 fast-forward pull했다. [구현 계획](plans/report-unification.md)에 따라 양쪽 저장소에 같은 `core/report_layout.py`를 두었다. 실행 중 서로의 저장소를 참조하지 않는다.

| 채택한 장점 | 반영 내용 |
|---|---|
| VXvue의 읽는 순서 | 요약·실제 시간 → 실패와 수동 확인 → TC 검색/필터 → 상세 → 환경·원본 |
| VXvue의 간결한 상세 | PASS 접기, Step 표1회, 긴 비고 접기, 원문/실제 비교, 인쇄 전체 펼침 |
| Bellalun의 판단 근거 | 등록 결함/연쇄 기록 표시, 해제 조건·미검증 범위, 구조화된 dict/list 값 |
| 공통 보존 | 0/False/None/빈 값 구분, 원본 결과·판정·JSON/CSV/TXT 계약, 제품별 등급 정책 |

같은 TC가 반복돼도 실행별 고유 링크를 쓴다. 필터로 숨긴 실행의 상세 링크를 누르면 필터를 해제해 목록과 상세가 함께 보인다. 인쇄 후에는 펼침·검색 상태를 복구한다.

## 시간 오류

WU 결과는 시험 후 체크리스트별 판정 객체를 생성한다. 그 객체의 시간 합계10.1분은 전체 시험 시간이 아니다. 새 소스는 실제 체인 시작·종료를 JSON meta.execution에 기록하고 HTML에 그 구간을 표시한다. 재개는 이번 실행만 계산한다. 전체 구간을 모르는 과거 WU 자료는 미기록으로 남긴다.

사용자 실행20261106-135549-c2057f5c는 GUI시작13:55:49~원본 보고서 생성15:47:26까지111.6분이다. 엔진 체인 로그는111.5분이며 보고서 생성 시간 포함 여부가 다르다. 원본 JSON과 HTML은 유지하고 `Result_WindowsUpdate_20261106_154725_time-corrected.html`을 별도로 만들었다.

## 실제 자료 검증

- Bellalun WU: 실제13 TC, PASS10/SKIP3. 기본기능은 과거 전체27 TC의 FAIL·MANUAL도 비교했다.
- VXvue: 로컬에서 확보한2026-11-04 실제 전체24행과2026-11-05 단독 TC01을 전후 비교했다. 클린PC1106 원본은 확보하지 못했다.
- Chrome에서 두 제품 전체 자료의 검색·판정 필터·빈검색·상세 펼치기/접기·앵커 연결·인쇄 전후 상태·모바일390px을 확인했다. 중복id·새 누락 링크·페이지 오류는0이다.
- VXvue의 D드라이브 외부 DICOM1개는 변경 전에도 존재하지 않았다. 그 파일을 복원하거나 데이터가 있다고 표시하지 않는다.
- 원본 JSON 해시와 TC/Step 판정은 보존했다. 공통 파일의 양쪽 SHA-256도 일치한다.

브라우저 세부 기록은 `work/unified-bellalun-browser.json`, `work/unified-bellalun-basic-browser.json`, `work/unified-vxvue-browser.json`에 둔다. 사내 원본·생성 보고서·화면은 공개 저장소에 넣지 않는다.

## 적용 범위

최종 소스 검사: Bellalun833 passed/4 skipped/269 subtests, VXvue전체selfcheck1,629건 실패·오류0·정적 문제0. 독립 검토에서 None/빈 문자열과 반복 TC의 실패 링크를 지적받아 실패 시험 후 수정했다. 양쪽 공통 계약·관련 검사와 실제 브라우저 검증을 다시 통과했다.

소스와 별도 재렌더 HTML에 적용했다. 현재 설치된 Bellalun1.0.2와 Setup은 변경 전5004de0 빌드다. 두 제품 설치판을 재빌드하거나 제품 시험·DB 복원·전체 회귀를 새로 수행하지 않았다. 장문 로그 때문에 GUI 완료 갱신이 늦는 문제는 별도 개선 항목이다.

### (2026-08-21) "Storage 활성 행 중복" — **자동화 판정 쿼리의 결함이었다**
<!-- archive -->
<!-- 이관 판단: 운영 지침 14-2 가 이 사고의 규칙을 영구 보관한다 -->


**증상**: 전체 회귀에서 `WF_04`(2D Send) 뒤 `CONFIGURATION.DICOM_STORAGE` 에 같은
서버(`BUNNY_TEST`)가 새 `Key` 로 늘어나고 둘 다 `Use=1` 이 됐다(Key 17 → 18 → 20).
"활성 Storage SCP 가 하나" 전제가 FAIL 해 `WF_05`/`WF_06` 이 전제에서 멈추고
`WF_15` 는 아예 중단됐다.

**첫 진단은 틀렸다.** Transfer Syntax 콤보를 팝업 rect 기준 절대 좌표
`(가운데, top+17)` 로 누르던 코드가 빗나가 `+`(2431) 추가 버튼을 눌렀을 것이라고
추정했다. 그 코드를 `uitext.pick_combo_by_text` 로 고치고 `setup-dicom` 단계에서
Transfer Syntax 를 미리 확정하게 한 뒤 연쇄를 다시 돌렸는데, `WF_04` 는
`changed=False`(Setting 을 **아예 열지 않음**)로 통과했음에도 **Key 18 이 또
생겼다.** 추정이 틀렸다는 증거였다.

**실측으로 확정한 진짜 원인** (세 가지 독립 근거)

| # | 확인한 것 | 결과 |
|---|---|---|
| 1 | 두 행의 전체 컬럼 비교 | `SCPUseType` 만 다르다 — Key 17 = `0`, Key 18 = `1`. 나머지 18개 컬럼은 동일 |
| 2 | `DATA.DICOM_STORAGE_QUEUE` 의 전송 작업 행 | `OriginalStorageKey=17` / `StorageKey=18` — **제품이 전송을 큐에 넣을 때 그 시점의 Storage 설정을 작업용 사본 행으로 복제하고 원본을 가리킨다** |
| 3 | Setting 각 페이지 목록 | `Storage` = `SCPUseType=0` 행 1개만 표시. `Storage Group` / `Storage Commitment` / `Query·Retrieve` / `MPPS` = 전부 0행 |

즉 **제품 결함도 아니고 자동화 상태 누수도 아니다.** 사용자가 나중에 서버 설정을
바꿔도 진행 중인 전송 작업이 자기 설정을 유지하도록 제품이 사본을 남기는 정상
동작이다. 결함은 그 사본까지 "설정된 활성 Storage SCP" 로 세던 **판정 쿼리**였다.
Send 를 한 번 할 때마다 "활성 SCP 가 하나 늘었다"고 오판정한 것이다.

이 사실을 드러낸 것은 **자동 복구 함수가 스스로 멈춘 메시지**였다 —
`"UI 목록 1행과 DB 2행이 달라 행을 짝지을 수 없습니다. 자동 복구를 하지 않습니다."`
애매하면 아무것도 하지 않게 만들어 둔 것이 오진을 막았다.

**조치**
1. **판정 쿼리를 `SCPUseType=0` 으로 좁혔다** — `ds.active_storage_rows`,
   `ds._stored_transfer_syntax`, `ds.repair_storage_use`, `setup_all` 의
   `Storage Use 단일 선택`·`Storage Transfer Syntax 단일 행 저장`,
   `WF_06`/`WF_07` 의 `SendDoseSR` 전제까지 전부. 상수는
   `ds.STORAGE_SCP_USE_TYPE` 이고 위 세 근거를 주석에 적어 두었다.
2. **사본 행을 관측으로 남긴다** — `ds.storage_job_copies` 가 `SCPUseType<>0` 행을
   읽어 전제 판정의 `actual.job_copies` 에 싣는다. 근거를 남기지 않으면 다음 사람이
   같은 오진을 반복한다.
3. **전제는 드러내기만 하지 않고 복구한다** — 설정 행이 그래도 여럿이면
   `ds.repair_storage_use` 가 UI(Storage 페이지의 Use 체크박스)로 하나만 남기고 DB 로
   다시 확인한다. `core/db.py` 조회 전용 원칙은 그대로다(DB 쓰기 없음). 복구 내용은
   `actual.repair` 에 남고 복구 실패는 FAIL 이다. 이 항목은 시험 대상이 아니라
   **전제(setup)** 이기 때문이다.
4. 첫 진단에서 고친 두 가지는 **원인과 무관하지만 그대로 유지한다** — 절대 좌표
   클릭 제거는 `AGENTS.md` 5절 준수이고, `setup-dicom` 단계 확정은 위험한 UI 조작
   횟수를 줄인다. 다만 **그것이 중복을 고쳤다고 적지 않는다.**

`setup-dicom` 에 판정 한 건이 늘었다: `Storage Transfer Syntax 단일 행 저장`
(설정된 활성 Storage 1행 + `TransferSyntax=0`). 2026-08-21 13:53 실측 PASS.

**교훈**: `DICOM_STORAGE` 처럼 한 테이블이 **설정 행과 런타임 행을 함께 담는** 경우가
있다. 구분 컬럼(`SCPUseType`)을 확인하지 않고 `WHERE [Use]=1` 만으로 세면 런타임
부산물을 설정으로 오판한다. 판정 쿼리를 쓸 때 **그 테이블에 다른 용도의 행이 섞여
있는지** 먼저 확인한다.

## 6. 2026-08-14 (2차) XIPL_06 해결 + 3D-W 확장 요약
<!-- archive -->
<!-- 이관 판단: 규칙은 운영 지침 7절(OCR psm)·8절(3D-N/3D-W 구분)로 승격됐다 -->


- **XIPL_06 블로커(Noise reduction 슬라이더 OCR) 해결.** 원인은 타이밍이나
  프로세스 경합이 아니라 **Tesseract `--psm` 선택**이었다. `psm 7`은 한 자리
  숫자를 빈 문자열로 버리고(선명한 "8"도 `''`), `psm 8`은 두 자리의 끝자리를
  중복시킨다("10"→"100"). `_ocr_integer`를 psm 6/7/8 × 전처리 2종의 **다수결
  투표**로 바꿔 5개 값 전부 안정적으로 읽힌다. 이전 세션의 "새 프로세스에서는
  성공한다"는 진단은 오진이었고, 그에 따라 들어갔던 서브프로세스 재캡처
  우회책은 제거했다. (자세한 규칙은 운영 지침 7절)
- **XIPL_06 Step 6 판정 근거 수정.** Viewer는 Parameter를 *선택*할 때
  `Image Process Param Name:...` 로그를 남기고 **Apply는 남기지 않는다**(실측).
  Apply 클릭 이후 구간에서 그 로그를 찾던 판정은 존재할 수 없는 증거를 기다린
  것이어서, 로그 증거는 선택 구간에서 확보하고 Apply 완료는 창 닫힘 +
  ImageAction 파일 생성으로 판정하도록 바꿨다. TC_04/05/06 모두 FULL로 승격.
- **3D-W(3D-Wide) 지원 추가.** Procedure `+` 다이얼로그의 Preset 탭 구조를
  실측해(2D=기본·LCC 802, 3D-N=탭 2083·852, 3D-W=탭 2084·902)
  `add_view_position`이 `"3d-w"`를 받도록 확장했다. Demo(F8)가 3D-W도 정상
  촬영함을 확인했고(동일 Series/Group에 InstanceType 1/2/3),
  `INSTANCE_GROUP.Type`/`ExposureMode`가 `1/1`=3D-N, `1/2`=3D-W로 종류를
  구분함을 기존 3D-N fixture와 대조해 확정했다.
- **신규 TC 2건 구현**: `tests/system_compat.py`의
  보조 항목 `AUTOMATION_3D_ACQUISITION_3DN`(3D-Narrow) / `_3DW`(3D-Wide),
  실행은 `python run.py run-sys3d`(회귀에도 포함). 등록·촬영·DB 구조/ExposureMode는
  자동 PASS/FAIL, 장비 LCD·2430 패들·회전 각도는 MANUAL로 분리 기록한다.
- **`flows.select_step()` 실제 버그 수정.** Step이 4개를 넘으면 아래 카드가 패널
  밖으로 잘리는데 `IsWindowVisible`은 visible로 보고한다. 잘린 카드의 center를
  클릭하면 선택이 바뀌지 않아 **F8이 기존 선택 Step을 촬영하고도 성공처럼
  넘어갔다**(3D-W 5스텝에서 실제 재현). 대상 카드를 패널 안으로 스크롤한 뒤
  클릭하도록 고쳤다.
